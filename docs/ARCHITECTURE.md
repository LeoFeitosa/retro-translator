# Architecture

Retro Translator plays a console game in its own emulator, learns the game's font from the screen, finds the game's
text in the ROM, translates it and writes it back, so the game draws the translation itself. What cannot be written
back is drawn over the screen while the game runs.

The code is split into **shared** modules, which know nothing about any console, and **isolated** modules, one
package per console. Adding a console must not change the shared code.

## Layout

```
retro_translator/                the program (everything it needs at run time)
├── __init__.py                  VERSION, HERE, DATA
├── __main__.py                  entry point: python -m retro_translator [GAME] [language]
├── app/                         the window: everything the player sees
│   ├── window.py                home, preparing and refusal screens, the game loop
│   ├── texts.py                 languages offered and what each screen says in each of them
│   ├── settings.py              the user's last choices; clean-up when a new version runs
│   ├── dialogs.py               file and folder pickers
│   └── updater.py               finds, downloads and installs a newer release
├── core/                        SHARED: no console, no window
│   ├── preparation.py           the preparation of a game (learn → translate → test → save), no screen
│   ├── reading/                 from screen pixels to text
│   │   ├── table.py             glyphs drawn on screen, collected while the game plays
│   │   ├── decipher.py          glyph → letter table (substitution cipher), language, proof by real words
│   │   ├── evaluate.py          collection of one game (cached) and accuracy of a table
│   │   ├── cjk.py               Japanese/Chinese reading (kana by font order, kanji by shape)
│   │   └── kana_kanji.py        kana → kanji conversion
│   ├── translating/             from text to text
│   │   ├── translation.py       routes per language pair, glossary, rules, fixes
│   │   ├── neural.py            offline neural model (Japanese, Chinese)
│   │   └── learn_rules.py       phrase rules (applied at run time; learned by tools/learn_rules.py)
│   ├── rewriting/
│   │   └── rom_text.py          finds the text in the ROM, fits the translation, writes and tests it
│   ├── overlay.py               the translation drawn over the screen
│   └── progress.py              progress of long steps for the preparing screen
├── consoles/                    ISOLATED: one package per console
│   ├── __init__.py              registry: CONSOLES, for_rom(path), extensions()
│   └── megadrive/
│       ├── __init__.py          the console contract (below)
│       ├── emulator.py          Genesis Plus GX through libretro (ctypes)
│       ├── rom.py               file formats (.bin, .smd), header, checksum
│       ├── core_patch/          our addition to the emulator core (C), built into lib/
│       ├── lib/                 built core (.dll / .so) — not versioned
│       └── system/              BIOS folder for the core — not versioned
└── data/                        data read at run time
    ├── glossary/ rules/ kanji/  versioned
    └── tables/ neural/ apertium/   built or downloaded — not versioned
tools/                           development only: never imported by retro_translator/
docs/                            this file
site/                            the website (generated by tools/site.py), published by .github/workflows/pages.yml
.github/workflows/               lint on every push; website deploy
```

Dependencies point one way only:

```
__main__ → app → core → consoles (through the registry only)
tools → anything
```

`core` never imports `app`; `consoles` never imports `core` or `app`; nothing in `retro_translator/` imports `tools`.

## The console contract

Every package in `consoles/` provides the same names. The shared code reaches a console only through
`consoles.for_rom(path)`, never by importing a console package directly.

| Name | What it is |
| --- | --- |
| `NAME` | Name shown to people ("Mega Drive") |
| `EXTENSIONS` | Game file extensions it opens (lowercase, with the dot) |
| `Emulator(path)` | The running game: `run_frames(n, buttons)`, `frame` (RGB array), `planes()`, `pattern(entry)`, `scroll(plane, y)`, `reg`, `save()`/`load(state)`, `write_rom(data, original)`, `audio_rate()`, `sound` |
| `read_rom(path)` | The ROM bytes in linear order, whatever the file format |
| `write_rom(original_path, data, path)` | Writes bytes back in the original file's format |
| `TEXT_START` | First offset where text may be rewritten (the header before it stays) |
| `data_end(rom)` | Where the ROM data ends |
| `checksum(rom)`, `HEADER_SUM`, `header_sum_valid(rom)`, `set_header_sum(rom)` | The game's own integrity check |
| `fix_checksum(rom, original)` | Keeps a rewritten ROM passing the game's check |

### Adding a console

1. Create `retro_translator/consoles/<console>/` with `__init__.py`, `emulator.py` and `rom.py` providing every name
   in the table above. Copy the shape of `megadrive/`; do not import from it.
2. Add the package to `CONSOLES` in `retro_translator/consoles/__init__.py`.
3. Put the built emulator core in its `lib/` (not versioned) and add how to build it to `tools/`.
4. Run `python -m tools.selfcheck` and the full check on a few games of the console (see CONTRIBUTING.md).
5. Update the console table in README.md, the public site and the repository descriptions.

If the shared code needs something a console cannot give through the contract, extend the contract (for every
console) instead of checking which console it is.

## Data

- Versioned (`data/glossary`, `data/rules`, `data/kanji`): small, edited by people or by tools in `tools/`.
- Not versioned (`data/tables`, `data/neural`, `data/apertium`, `consoles/*/lib`, `consoles/*/system`): built by the
  scripts in `tools/` or downloaded; `tools/package.sh` puts them into the executable.
- The user's own data (learned games, settings, reports of unreadable games) lives in
  `~/.retro-translator` (`core/preparation.FOLDER`), never next to the program.
- Development output (`captures/`, `memory/`, `output/`, `results.jsonl`, logs) lives at the repository root and is
  not versioned.

## Rules

These hold for every change. A change that needs to break one updates this file first, with the reason.

1. **Shared or isolated.** Code that depends on a console goes in `consoles/<console>/`. Code that does not goes in
   `core/`. The window (`app/`) only shows things and asks; it holds no reading, translating or ROM logic.
2. **One direction.** Follow the dependency arrows above. No circular imports, no `tools` imports from the package.
3. **No per-game lists.** Every fix must work for any game: no game names, no per-game tables or exceptions.
4. **Never write what was not proven.** A letter is used only when real words prove it; a message is written into
   the ROM only when it was read whole. When in doubt, leave the original text: a wrong translation is worse than
   none, and the program must say so instead of claiming success.
5. **Offline and light.** Runs on the CPU, without internet (except the update check), on any Windows PC. A new
   dependency must replace more than it adds.
6. **Native first.** Use the standard library and what the project already has before adding code or packages.
7. **English only** in code, comments, commit messages and everything published on GitHub. The program's screens are
   translated through `app/texts.py`.
8. **Entry points.** The program starts only from `retro_translator/__main__.py`; development commands live in
   `tools/` and run from the repository root as `python -m tools.<name>`. Modules in `retro_translator/` have no
   `if __name__ == "__main__"` block.
9. **Paths.** Data paths come from `retro_translator.DATA` (or the console package's own folder); never from the
   working directory, which is the user's folder while the program runs.
10. **Versions.** Raise `VERSION` in `retro_translator/__init__.py` before every release; older builds offer the
    update when the published release is newer.
